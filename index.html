TravelEcosystem
SaaS & B2B Marketplace

A globally distributed, multi-tenant operational engine for travel agencies, guides, OTAs, and partners. Re-engineered from the UWT backend into a cloud-native, AI-augmented platform built for "Elite Simplicity."

GCP / GKE Multi-tenant Event-driven Vertex AI B2B Marketplace Real-time GPS iCal / XML Sync OCR Fraud Detection White Label

TravelEcosystem is not a simple booking app — it is an operational engine that combines financial precision, real-time logistics, and cross-agency commerce into one zero-friction interface. The core is a re-engineering of the existing UWT backend, modernised into a marketable SaaS with an AI-augmented layer built on Phase 2.

07 Kubernetes / GKE Design

Topology Strategy

The cluster is partitioned into functional namespaces with strict Istio network policies to prevent lateral movement between tenants and services.

HPA + KEDA Scaling

Pods scale on CPU/RAM via HPA. Async workers scale on Pub/Sub queue depth via KEDA for rapid burst handling during cruise ship arrivals.

Istio Service Mesh

Enforces mTLS between all services. Provides circuit breaking, L7 traffic management, and distributed tracing via OpenTelemetry.

08 VPC Networking Architecture

A private-first VPC topology ensures no microservice or database is exposed to the public internet. Ingress is strictly mediated by the Global Load Balancer and Kong.

09 Database Architecture & Topology

Multi-database strategy to balance ACID guarantees for financial data with sub-millisecond real-time updates for GPS, chat, and availability.

Relational / ACID
Cloud SQL (PostgreSQL 15)

Primary store for booking and financial ledgers. Per-tenant physical instance isolation. Supports multi-currency settlement (CZK, EUR).

Real-time / Sync
Cloud Firestore

High-frequency updates for GPS streams, in-app chat, and traveler-facing booking status. Multi-device sync out of the box.

Distributed Cache
Memorystore (Redis 7)

Distributed SETNX locking during booking to prevent over-capacity. Session caching and rate-limiting buckets for rapid API response.

Tenant Isolation Strategy

Agency onboarding triggers an automated Cloud Function provisioning a dedicated Cloud SQL instance — zero cross-tenant data leak risk. Simplifies GDPR compliance per jurisdiction.

22 Security Architecture

Network
Zero Trust (mTLS)

Istio ensures all service-to-service communication is encrypted and mutually authenticated. No cleartext inter-service traffic permitted.

Identity
Workload Identity

GKE pods assume GCP IAM roles without long-lived keys. Principle of least privilege enforced at namespace level.

Data At Rest
CMEK Encryption

All persistence layers use Customer-Managed Encryption Keys via Cloud KMS with automatic 90-day rotation.

26 Production Readiness Review

Critical Risk — Instance Overhead at Scale

1,000+ Cloud SQL instances introduces management toil. Mitigation: Implement a tier-based system where small agencies share instances via schema isolation. Tier-1 enterprise tenants maintain dedicated infrastructure.
